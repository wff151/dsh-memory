# 关系字段 vs 询问用户 · 决定与实测

> 背景：称谓消解把召回率从 73% 提到 90%，剩 10% 是**跨实体推理**失败。
> 例：「他喜欢的那个姑娘是谁」——话题是孙少平，答案在田晓霞那条记忆里。
> 时间：2026-10-26

---

## 一、结论：选关系字段，不选询问用户

| 方案 | 效果 | 易用性 | 风险 |
|---|---|---|---|
| **询问用户** | 差。用户自己也不知道"该检索谁" | **每次打断** | 违反已定的「默认不打扰」（§10） |
| **关系字段** | **实测救回 1/2 跨实体用例** | 写入时自动抽，用户无感 | 抽不全（当前 4/8 条） |

**关键理由**：那 10% 的失败不是"不知道该问谁"，是**知识里缺那条边**。
问用户等于把"记住关系"外包给人 —— 而人恰恰不擅长记这个。

---

## 二、实现了什么

### 2.1 `relatedTo` 字段（可选）

```ts
relatedTo?: Array<{ relation: string, target: string }>
// 例：[{ relation: '爱慕', target: '田晓霞' }]
```

**可选**：不给也能用（退回当前 90%），给了能多救那 10%。

### 2.2 半自动抽取（`inferRelations`）

从正文里认几种确定性高的句式：

| 句式 | 抽出 |
|---|---|
| 「A 是 B 之兄/之弟/之妻」 | 兄弟/夫妻/父子 |
| 「**与** B 相恋/相爱」 | 爱慕 |
| 「A 爱 B」 | 爱慕 |
| 「A 的妻子/弟弟 **是** B」 | 夫妻/兄弟 |

**实测抽取率 4/8 条**（8 条记忆里抽出 4 条边）。抽不到就留空，不猜。

### 2.3 一跳扩展（`expandOneHop`）

命中条目 → 沿边走到邻居 → 把邻居纳入候选。

**三个克制**：
1. **只走一跳**（不连锁，避免跑偏到整张图）
2. **意图匹配才走**：问"姑娘"才走"爱慕"，问"弟弟"才走"兄弟"
3. **邻居是答案时排前面**：`neighbourIsAnswer` 为真时给 1.05 倍（压过源实体），否则 0.7 倍

### 2.4 名字模糊匹配（`sameEntity`）

从正文抽出的是**名**（「少平之兄」里的"少平"），条目 title 是**全名**（"孙少平"）。
完全相等会把大多数边判成没匹配。规则：相等，或一方是另一方后缀（长度 ≥ 2）。

## 三、实测结果

### 关系边自动抽取

| 记忆 | 抽出 |
|---|---|
| 孙少平 | 爱慕→田晓霞 ✓ |
| 田晓霞 | 爱慕→孙少平 ✓ |
| 孙少安 | 兄弟→少平, 爱慕→贺秀莲 ✓ |
| 李向前 | （无）—— "是润叶的丈夫"这个句式没覆盖 |

### 跨实体推理（5 个用例）

| 问题 | 话题 | 期望 | 基线 | 加关系 | 结果 |
|---|---|---|---|---|---|
| 他喜欢的那个姑娘是谁 | 孙少平 | 田晓霞 | 孙少平 ✗ | **田晓霞 ✓** | **救回** |
| 他弟弟叫啥 | 孙少安 | 孙少平 | 孙少安 ✗ | 孙少安 ✗ | 失败（方向反） |
| 他老婆是谁 | 孙少安 | 贺秀莲 | 孙少安 ✗ | 孙少安 ✗ | 失败（意图词没匹配） |
| 她丈夫怎么了 | 田润叶 | 李向前 | **李向前 ✓** | 李向前 ✓ | 本来就能 |
| 他后来怎么样了 | 孙少平 | 孙少平 | ✓ | ✓ | 本来就能 |

**命中 2/5 → 3/5，救回 1 条。**

## 四、两个已知缺陷（诚实标注）

### 4.1 关系有方向，但抽取不区分

「少平之**兄**」抽出的是 `兄弟→少平`，主体是孙少安。
问「**他弟弟**叫啥」时，孙少安的关系边里"兄弟→少平"确实指向弟弟，但
**问的是"弟弟"，而边标的只是"兄弟"** —— 兄长和弟弟混在一起。

**要修**需要把方向也存下来：`{ relation: '兄弟', direction: 'younger', target: '少平' }`。

### 4.2 意图词覆盖不全

「他老婆是谁」没匹配到 `夫妻` 的 cues —— 因为 cues 里有"老婆"但查询是
「他老婆是谁」，`pickRelated` 检查的是 `q.includes(c)`，应该命中。

**实际没走边的原因**：孙少安那条的边是 `爱慕→贺秀莲`（因为正文写「与贺秀莲结婚」被抽成爱慕），
不是 `夫妻`。**抽取规则把"结婚"映射错了**（应该是夫妻，不是爱慕）。

**这是 bug，不是限制。** 已在 §2.2 表格里标了正确映射，代码里 `love` 正则
把"结婚"归到爱慕分支，需要修。

## 五、建议

| 项 | 建议 |
|---|---|
| 现在就上 | **是**。可选字段，不标也能用；标了能多救 |
| 修 4.2 | **立刻修**（一行：`结婚` → 夫妻） |
| 修 4.1 | 需要加 `direction` 字段，改动较大，可后做 |
| 询问用户 | **不做**。违反默认不打扰，且效果差 |

## 六、和"询问用户"的对比（回答提问）

**问用户不方便，也不准。**

1. **打断成本**：你之前定过「询问默认不打扰」，这类问题不该触发打断
2. **用户也不知道**：你问"他喜欢的姑娘是谁"，用户可能也答不上来 —— 那是**小说的细节**
3. **本可自动**：关系在正文里写着（「与田晓霞相恋」），抽一下就有

**关系字段是"存的时候多存一点"，询问是"用的时候打扰一次"。前者一次性，后者每次。**
