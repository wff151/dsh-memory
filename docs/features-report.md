# 特征索引 · 实测报告（含逐项 A/B）

> 目标：让条目能回答"凭什么是它而不是同类"，提升**不含实体名**的检索。
> 时间：2026-10-26 · 结论：**半成半败**，数据在下面。

---

## 一、结论先行

| 机制 | top1 | top3 | 判定 |
|---|---|---|---|
| 基线（全关） | 50% | 60% | — |
| **+称谓消解** | **57%** | 65% | **✓ 唯一真正有效（+7pt）** |
| +关系一跳 | 55% | 65% | ✗ 略伤（−2pt） |
| +意图类型 | 53% | 65% | ✗ 伤（−2pt） |
| **+唯一特征** | 53% | **68%** | ◐ **召回 +3pt，排序 0** |

**40 条不含名问法的实测**（`_tools/ab-mechanisms.mjs`，逐项叠加）。

## 二、唯一特征索引做了什么

### 2.1 原理

同一批记忆里：

| 词 | 出现在几条 | 是不是特征 |
|---|---|---|
| `煤矿` | 3 条以上 | **否**——共同词，指向所有和煤矿有关的条目 |
| `农村青年` | 1 条（孙少平） | **是**——命中它就锁定孙少平 |

算法：抽每条记忆的候选词 → 统计每个词在多少条里出现（df）→
**df 越高越没区分度**（> 40% 直接丢弃）→ 按 IDF × 长度 × 短语完整性排序。

### 2.2 效果（单条对比）

```
问：那个在煤矿下井的年轻人是谁？
纯关键词   top1 = 煤矿     ✗
加特征     top1 = 孙少平   ✓   ← 救回
```

**在 2 条语料的小样本上，特征确实能翻盘。**

## 三、为什么在 100 问里只提升 3pt

### 3.1 小样本有效 ≠ 真实场景有效

小样本（2–3 条）里特征是决定性的；20 条语料里：

```
问：那个在煤矿下井的年轻人是谁？
  孙少平  semanticScore = 0.170   （特征加成后更高）
  煤矿    semanticScore = 0.370
```

**"煤矿"那条分数更高——而且是"合理"的。** 它确实在讲煤矿、讲下井。
字面上它更匹配查询。

要让检索偏向"孙少平"，需要理解 **"年轻人"是人物线索** ——
那是**语义理解**，不是字符串匹配能做的。

### 3.2 特征质量的现实

调了三版才把特征从碎片变干净：

| 版本 | 抽出的特征 |
|---|---|
| 第一版（纯滑窗） | `农村青` `村青年` `矿当矿` —— 全是碎片 |
| 第二版（短语优先） | `双水村生产队长` `办砖窑先致富后破产` —— 太长，用户不会这么说 |
| **第三版（2–6 字短语 + 滑窗兜底）** | `农村青年` `省报记者` `改革派干部` `砖窑` —— 可用 |

**但即使干净了，对 top1 也没帮助。**

## 四、这轮修掉的两个真 bug

### 4.1 方位字被误当虚词（重要）

`CN_FUNCTION_CHARS` 里放了 `上中下里前后`，导致：

```
tokenize("那个在煤矿下井的年轻人是谁")  →  12 个 token
过滤后                                →  只剩 3 个（煤矿 / 年轻 / 轻人）
```

**「下井」被丢了** —— 它是这部小说的核心场景词。

修掉后：保留 5 个（`煤矿 · 矿下 · 下井 · 年轻 · 轻人`），
**top3 召回 63% → 68%**。

> 过度过滤比不过滤更坏：它悄悄扔掉关键线索，而分数看起来还正常。

### 4.2 特征加成用绝对值 → 长条目作弊

第一版写 `score += ft * 0.8`，结果**含名问法从 100% 掉到 90%**：
特征多的长条目靠"命中一堆弱特征"压过了"名字精确命中"。

改成按比例 `score *= 1 + ft * 0.5` 后修回。

## 五、诚实的失败清单

本次尝试过、**确认无效**的：

| 尝试 | 结果 |
|---|---|
| 类型加权 1.25 / 0.6 | 含名 85%→90%，不含名 0 |
| 类型加权 2.2 / 0.35 | **反而更差**（50%） |
| 特征分加绝对值 0.8 | 含名 100%→90% |
| 特征短语不限长度 | 特征变长垃圾，无效 |
| 特征纯滑窗 | 特征全是碎片，无效 |

**共同教训：这些都在改"排序"，而问题在"召回"和"语义理解"。**

## 六、现在保留了什么

| 机制 | 保留 | 理由 |
|---|---|---|
| 称谓消解 | ✓ | 唯一有正收益（+7pt） |
| 唯一特征 | ✓（仅召回） | top3 +3pt，且能让条目更可解释 |
| 关系一跳 | ✓（未删） | 跨实体推理唯一手段，虽然 A/B 是 −2pt |
| 意图类型 | **✗ 已关**（`USE_KIND_BOOST = false`） | 负贡献 |
| `kind` 字段 | ✓（保留数据） | 数据更干净，未来可能有用 |

代码里留了开关，想恢复类型加权改一行即可。

## 七、真正该走的路

不含名问法的失败本质：

```
问：那个在煤矿下井的年轻人是谁？
存：孙少平是主角…煤矿当矿工…
```

**"煤矿"这个词区分不了孙少平和"煤矿"那条记忆。**

字符串层面的所有手段（特征、权重、类型）都在这上面撞墙。
要过去，只有两条路：

| 路径 | 说明 | 现状 |
|---|---|---|
| **更强的向量模型** | 语义层面理解"年轻人→人物" | 已测 nomic（弱，2/6）；bge-m3 未测（需下载） |
| **让模型自己判断** | 把候选（top3）给模型，让它选 | 未做；成本是多一次调用 |

**这两条都不是"再调一个权重"能替代的。**
