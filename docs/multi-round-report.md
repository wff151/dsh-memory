# 多轮实测报告（第 2 轮·重启后）

> 时间：2026-10-26 · 100 问 × 20 个实体 ·《平凡的世界》
> 目的：拿到**足够多的数据**，看这套记忆检索的真实水平在哪。

---

## 一、最重要的发现：含名 / 不含名 差 47 个百分点

| 问法 | 题量 | top1 | top3 |
|---|---|---|---|
| **含实体名**（"孙少平后来怎么样了"） | 60 | **100%** | 100% |
| **不含名·只描述内容**（"那个在煤矿下井的年轻人是谁"） | 40 | **53%** | **60%** |

**完全 miss：15/100（15%）。**

**这个差距就是全部问题的所在。**

---

## 二、失败模式（15 条完全 miss）

全部集中在「**不含名·只描述内容**」这一类：

| 问法 | 期望 | rank |
|---|---|---|
| 那个在**煤矿下井**的年轻人是谁？ | 孙少平 | -1 |
| 在**抗洪**里救人死的是谁？ | 田晓霞 | -1 |
| 办**砖窑**的那个人是谁？ | 孙少安 | -1 |
| 考上**大学学物理**的那个女孩是谁？ | 孙兰香 | -1 |
| 当兵时爱上**藏族姑娘**的那个人是谁？ | 金波 | -1 |
| 那个**地委书记**是谁？ | 田福军 | -1 |
| 矿上那个**寡妇**是谁？ | 惠英嫂 | -1 |
| **故事发生在哪个村**？ | 双水村 | -1 |
| 烧出**废砖破产**的那档子事 | 砖窑 | -1 |

**共同点：描述里全是"特征词"（煤矿、抗洪、砖窑、寡妇），而条目 title 是"名字"。**

`semanticScore` 会给"特征词命中"打分（`inBody` 分支 0.85），但**特征词太通用**——
"煤矿"命中孙少平那条，也命中"煤矿"那条、也命中"井下"那条，分不开。

---

## 三、测试本身也踩过两个坑（诚实记录）

### 3.1 第一版：给每问都设了 topic = 本实体 → 100%

等于**把答案喂进查询**。删掉 topic 后仍是 100%，因为题目还含实体名。
直到加入"不含名"的问法，才看到真实的 53%。

> **教训：测试结果"太完美"时，先怀疑测试，不是庆祝。**

### 3.2 上一轮 77% 那个数字的口径

那个测试是「每个实体先登记、再换 3 种问法追问」，其中**大部分问法含实体名**。
所以 77% 和这次的 81% 不矛盾——**口径不同**。

真正的困难场景是这次新加的 40 问：**53%**。

---

## 四、根因分析

### 4.1 条目「title = 名字」，没有"特征索引"

一条记忆长这样：

```
title  : 孙少平
summary: 主角，农村青年。后到铜城大牙湾煤矿当矿工，井下黑暗闷热。与田晓霞相恋。
```

问「那个在煤矿下井的年轻人是谁」→ 命中了 `煤矿` 这个词，
但 `煤矿` 在**多条**里都有（孙少平、煤矿那条、井下那条），分不出主次。

**条目缺一个"这是什么"的索引**：`type: 人物 | 地点 | 事件`，
以及**唯一性特征词**（孙少平 = 主角+煤矿；煤矿 = 铜城+井下）。

### 4.2 为何"含名"就 100%

因为 `title` 就是名字，`isPlausibleToken` + 位置加权让 title 命中给满分。
**名字是最强信号**——有名字就稳，没名字就靠特征硬碰。

---

## 五、修复方向（下一步）

| 序 | 改什么 | 预期 | 代价 |
|---|---|---|---|
| 1 | **条目加 `type`**（人物/地点/事件），查询按意图收窄 | 问"谁"只搜人物 | 中（改 schema + 写入侧） |
| 2 | **写"唯一特征"**：写入时抽条目的独有词 | 特征命中能区分 | 中 |
| 3 | **问题类型识别**：先判"问的是谁/哪/什么"，再定向检索 | 砍掉 2/3 候选 | 小（纯函数） |
| 4 | **关系网补足**（已做）：`relatedTo` 一跳 | 跨实体推理 | 已做 |

**第 3 项最便宜**：从提问词（谁 / 哪 / 什么时候）推意图类型，比改 schema 快。

---

## 五之二、第 3 项做了，**基本失败**（诚实记录）

实现了 `intent.ts`：
- `detectAnswerKind(query)` → 从「是谁 / 哪里 / 什么时候 / 什么事」判期望答案类型
- `inferEntryKind(title, text)` → 写入时自动给条目打 `kind`（person/place/event）
- `kindMatches()` → 类型匹配的 ×1.25，不匹配的 ×0.6

**类型推断本身是准的**（20 条：12 人物 / 5 地点 / 1 事件，全对）。

**但效果几乎没有**：

| 指标 | 加类型前 | 加类型后 |
|---|---|---|
| top1 总 | 81% | **79%**（先掉到 78%，修了推断顺序才回 79%） |
| 不含名·内容 | 53% | **53%**（**一点没动**） |
| 含名·场景 | 100% | 100% |

**为什么失败**：类型加权只能调整**已召回**条目的排序。
而不含名问法的失败是 **rank=-1（根本没召回）** ——

> 排序修不了召回。

**这是一次负优化又救回来的过程**：
1. 第一版 `inferEntryKind` 把「孙少平是主角…煤矿矿工」判成 `place`（因为正文有"煤矿"）
2. 导致 4 个人物类别错，含名问法从 100% 掉到 85%
3. 改成**先判人名**（2–4 字 title + 人物特征词）后修回来

**结论**：类型信息值得保留（数据更干净，未来有用），
但**不能指望它提升不含名检索** —— 那需要改**召回**，不是改排序。

---

## 五之三、真正的下一步：改召回，不是改排序

不含名问法失败的共同形态：

```
问：那个在煤矿下井的年轻人是谁？
存：title=孙少平, summary=主角，农村青年。后到铜城大牙湾煤矿当矿工…
```

"煤矿"这个词**在 3 条以上记忆里出现**（孙少平、煤矿那条、井下那条），
所以它**不是区分特征**，是共同词。

要让它成为特征，需要知道 **"孙少平"这个条目独有的是什么**：

| 条目 | 区别于同类的特征 |
|---|---|
| 孙少平 | 主角 · 煤矿 · 与田晓霞相恋 |
| 孙少安 | 兄 · 砖窑 · 贺秀莲 |
| 田晓霞 | 记者 · 抗洪 · 牺牲 |

**即：每个条目要能回答"凭什么是它而不是同类"。**

这件事**不是打分能做的**，需要在写入时抽取**唯一特征词**并建立索引。
成本比 type 大，但那是唯一能提升召回的方向。

**已确认不值得做的**：
- 继续调打分权重（已调两轮，边际收益递减）
- 加类型加权（本轮已证伪）


---

## 六、当前所有改动带来的净效果

| 阶段 | 指标 |
|---|---|
| 最初（slice 截断时代） | 没有任何语义检索 |
| 分数加连续项 + 过滤垃圾片 | top1 并列 50% → 20% |
| 称谓消解 | 追问场景 top1 60% → 77%，召回 73% → 90% |
| 关系网一跳 | 跨实体推理 0/2 → 1/2 |
| **含名问法** | **100%** |
| **不含名问法** | **53%** ← 待改进 |

---

## 七、结论

**这套检索的上限和下限都已经量清了：**

- **有名字** → 几乎不会错（100%）
- **只有描述** → 一半会丢（53%）

"老年痴呆"的真相不是"记不住"，而是：
**用户用描述问，记忆用名字存，两边对不上。**

下一步该做的是**让条目知道"自己是什么"**（type + 唯一特征），
而不是继续调打分权重 —— 权重已经调过两轮，边际收益在递减。
